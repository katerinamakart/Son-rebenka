## Публикация

GitHub Pages публикует корень ветки `main` (Source: Deploy from a branch, `/(root)`). Маркер `.nojekyll` отключает обработку Jekyll: `index.html` и закреплённая копия Supabase JS 2.119.0 в `supabase-2.119.0.js` передаются как готовые статические файлы. Штатный `pages-build-deployment` запускается при изменении `main`. Прежний `.github/workflows/static.yml` оставлен только для ручной диагностики/восстановления; автоматический push-триггер убран, чтобы не запускать два конкурирующих выпуска. Ручной workflow не является текущим источником публикации; для возврата к нему нужно отдельно выбрать Source: GitHub Actions.

## Данные и семейный доступ

- Без входа анкеты, отдельные дневники детей и черновики хранятся в localStorage. Старые данные ключа `son-rebenka-simple-v15` читаются при первом запуске новой версии и не удаляются.
- Начало повторной проверки сохраняет выбранного ребёнка и его дневник. Кнопка добавления ребёнка создаёт отдельный профиль.
- Семейный аккаунт использует Supabase Auth: email, пароль и подтверждение email. Один аккаунт соответствует одной семье; приглашения отдельных взрослых пока не реализованы. Другие устройства входят в тот же аккаунт.
- Данные разных аккаунтов разделены в localStorage. Гостевые анкеты импортируются отдельно кнопкой; они не отправляются автоматически.
- В Supabase синхронизация явная: «Сохранить в аккаунт» сохраняет выбранного ребёнка, «Показать записи аккаунта» позволяет загрузить копию. При конфликте версий запись отклоняется, локальные данные сохраняются. Перед загрузкой серверной версии можно экспортировать локальный JSON из дневника.
- `sleep_profiles`, `sleep_entries`, `sleep_statistics_consent`: RLS, доступ только при `auth.uid() = family_id`, гостевой роли доступ закрыт. Внешний ключ запрещает прикрепить запись к профилю другой семьи. `save_sleep_family` — SECURITY INVOKER, атомарная запись с проверкой версии.
- В клиенте только публичный publishable key. Пароли и service_role/secret keys в репозитории не хранятся.
- Отдельное согласие на статистику по умолчанию выключено и отзывается независимо от дневника. Сбор и выдача общей статистики пока не включены: публичных таблиц/представлений со сведениями семей нет. Перед запуском статистики нужен отдельный агрегатор, учитывающий согласие, удаляющий идентификаторы/точные даты/тексты и подавляющий малые группы.

Полная схема: `schema.sql`. Уже применена к существующему проекту `Son-rebenka` (`plyhrthxqmlkcqqqhmkz`). На действующей базе повторно весь файл не запускать; он описывает создание новой пустой схемы.

## Настройка Auth и оставшиеся действия владельца

В Supabase Dashboard → Authentication:

1. Уже настроено и проверено в панели: Site URL `https://katerinamakart.github.io/Son-rebenka/`, этот же адрес добавлен в Redirect URLs. Email Auth, регистрация и подтверждение email включены. Вместо localhost используется рабочий адрес сайта.
2. Email provider: оставить подтверждение email включённым. Для пользователей вне команды проекта подключить свой SMTP: встроенная почта Supabase предназначена для тестов и ограничена разрешёнными адресами.
3. Проверить регистрацию на своей почте, подтверждение, вход на втором устройстве и явную загрузку дневника. Секрет SMTP хранится только в Supabase Dashboard.
4. При желании включить защиту паролей и настроить лимиты/антиспам Auth перед массовым распространением.

Вход владельца в панель выполнен, настройки URL сохранены. Собственный SMTP не подключён: для его настройки нужен выбор почтового сервиса владельцем и безопасный ввод его SMTP-данных в панели. Регистрация и доставка настоящего письма не подтверждены тестами. Локальный режим от почтовой настройки не зависит.

## Анкета 1.8

Шесть последовательных шагов: возраст, режим, утреннее пробуждение, вечернее поведение, занятия/нагрузка дня, условия сна. Обязателен возраст; неизвестные значения сна остаются неизвестными. Множественный выбор допускает совместимые наблюдения; «не знаю», «по-разному», «не относится» исключают конкретные ответы в своей группе. Школа, сад, занятия и новые навыки фильтруются по возрасту. При его изменении несовместимые ответы удаляются.

Часы и минуты выбираются отдельными стандартными элементами управления, включая дневник. Частично выбранное время не считается корректным. Старые ответы и дневники сохраняются; экран старой анкеты переводится на шаг условий. Новые поля сохраняются существующим механизмом семейных анкет, изменения схемы базы не требуются.

Использованы только общие категории структуры частных образцов: режим, настроение, укладывание и условия. Содержимое частных документов, ответы, контакты, медицинские сведения и ссылки на них не включены в сайт, тесты или базу.

Результаты показывают сначала диапазон рекомендации и известные фактические длительности, затем отклонение, вывод и осторожные наблюдения о контексте. Активность, впечатления, скачок роста и вечернее поведение не считаются доказанной причиной и не изменяют норму сна. Источник общих рекомендаций по ритуалам и среде: American Academy of Pediatrics, ссылка в результатах.

Мобильные тесты обновлены для шести шагов: младенец, дошкольник, школьник, возраст 35/36 месяцев, пропуски и смешанные ответы, исключающие варианты, сохранение после возврата/обновления, часы/минуты, дневник и семейный аккаунт. Необходим `test-helpers.cjs` рядом с `mobile.cjs` и `edge-cases.cjs`. Публичные тесты используют только искусственные ответы.

## Распределение сна и неделя (1.9.0)

Для детей с 4 месяцев дневные сны задаются отдельными интервалами. Можно добавлять и удалять сны; режимы «не знаю», «не было» и сохранённая старая сумма различаются. Вычисляются сумма снов, ночной сон за вычетом бодрствования, общий сон, промежутки между снами, последний промежуток до засыпания и длительность укладывания. Часы/минуты ночного бодрствования не требуют ручного перевода в минуты. При пересечении снов, неполном времени или нарушении порядка времени приложение просит исправить данные. Ночной переход через полночь поддерживается.

Результат содержит три независимых раздела: продолжительность, распорядок, качество. Показатели распорядка описательные: универсальной нормы бодрствования нет. Пример 16:00–18:00 и укладывание в 20:00 даёт 2 часа до укладывания. Возможная неготовность ко сну — гипотеза, а не диагноз. Самочувствие днём отмечается отдельно. До 4 месяцев сохранён гибкий режим с дневной/ночной суммой. Источник общей оговорки о поздних дневных снах: https://www.nhs.uk/baby/health/sleep-and-young-children/ .

Недельный анализ использует выбранный день и 6 предыдущих календарных дней. Даты дедуплицируются. Средние считаются только по полным дням с известным общим сном; отдельно указано покрытие ночных/дневных значений. Показываются расписание каждого дня и средние времена (круговое среднее для времени суток). Описательные сопоставления доступны от 3 полных записей, подробное сопоставление дневного/вечернего времени — от 3 записей с интервалами. Будни и выходные сравниваются при наличии минимум 2 полных дней каждой группы. Эти пороги — ограничения объёма данных в интерфейсе, не доказательство статистической значимости.

Новая запись датируется днём дневных снов и включает следующую ночь. Прежние даты и суммы не меняются. Старые записи участвуют в средних длительностях; недостающие интервалы не восстанавливаются искусственно. JSON записей дополнен schemaVersion, napMode, naps, bedtime и nightWakings. Схема Supabase, RPC, политики семейного доступа и согласие на статистику не менялись; новые поля проходят в существующем JSON payload. Автоматической отправки новых данных нет.

Проверка этой версии (05.11.2026): `npm test` — 39 проверок расчётов, трёх снов, интервалов, полуночи, пересечений, неизвестных значений, младенца, старых записей, периода 7 дней, пропусков, повторных дат и будней/выходных. В браузере на мобильных viewport 320 и 390 px проверены шесть шагов, три сна/удаление, предупреждение о пересечении, возврат и обновление, уточнение неполного результата, перенос расчёта в дневник, сохранение и просмотр записей, недельный экран с 7 полными днями, отказ от выводов по 2 дням, младенческий дневник и раздельные профили. Шаблон 430 px также проверен на переполнение. Тестовые записи искусственные, только в браузере предпросмотра, в Supabase не отправлялись. Текущая проверка облака ограничена состоянием RLS и Security Advisor; реальная регистрация, SMTP и вход второго устройства повторно не тестировались. `npm run test:mobile` оставлен как воспроизводимая автоматическая регрессия, в этой сессии проверка интерфейса выполнена через браузер.

Первый промежуток бодрствования показывается только при известном начале дня; интервалы между снами и до засыпания считаются и без него. При отсутствии дневного сна последний промежуток считается от необязательного начала дня до фактического ночного засыпания. Проверены и разные подъёмы, и день без дневного сна.

## Простой сценарий без регистрации (1.9.1)

Анкета, анализ одного дня/недели и локальный дневник доступны без регистрации, пароля и подтверждения почты. На главной явно показаны автоматическое сохранение в текущем браузере и число записей. Раздел «Сохранение и перенос данных» свёрнут; в нём есть скачивание копии и отдельный вложенный доступ к ранее созданным аккаунтам. Новая регистрация из интерфейса убрана. Существующие Auth-пользователи, семейные пространства localStorage, Supabase/RLS и облачные записи не удаляются и не объединяются автоматически. При открытии сайта с ранее сохранённого экрана аккаунта показывается главная.

Объяснено, что дневник относится к конкретному браузеру: встроенный просмотрщик Threads/Instagram/почты может иметь отдельное хранилище. При ошибке localStorage сайт показывает предупреждение вместо успешного статуса. Кнопки прежней формы входа расположены одним столбцом; пароль не обещается в письме. Дополнительные действия не требуются для основного сценария.

Проверки этой версии: `npm test` — 49 проверок, включая прежние расчёты, сохранность дневника и корректный статус при отказе/восстановлении записи в хранилище. Мобильные проверки через браузер: отсутствие входа/регистрации на основном экране, запись без аккаунта, обновление страницы, необязательный прежний вход и возврат без авторизации. Успех публикации на Pages проверяется отдельно; описание прежней блокировки выпуска приведено выше.

Проверена также сохранность произвольной длительности ночного бодрствования в черновике дневника после обновления. При отказе записи в хранилище предупреждение появляется и в самом дневнике, а не только на главной.

Публичная проверка 1.9.1: без входа пройдена анкета, рассчитаны ночной сон 10 ч, дневной 2 ч, общий 12 ч; для сна 16:00–18:00 и укладывания в 20:00 показаны 2 ч бодрствования до укладывания. Синтетическая запись сохранилась после обновления страницы. Секреты и реальные сведения детей не использовались. Локальный набор — 49 успешных проверок.

## Версия 1.10.1 — сравнение режима

Вместо «Примера распорядка» добавлено сравнение: этап дня, фактические ответы, гибкий ориентир и комментарий. На ширине до 650 px строки становятся карточками. Возрастные варианты числа снов учитывают месяцы и постепенные переходы; лишние отдельные строки скрываются, дополнительные реальные сны остаются в сумме и сводке. Неизвестные и старые суммарные записи не объявляются пропусками. Вечерняя граница — обратный расчёт от нижнего суточного ориентира, следующего подъёма, дневного сна и ночного бодрствования, а не универсальное время по часам. Младенцам до 4 месяцев точная граница не назначается. Подсветка близкого дневного сна требует одновременно до 2 часов до укладывания и укладывания от 30 минут; это явно обозначенное правило интерфейса для наблюдения, не медицинская норма. Длительное бодрствование рассматривается вместе с недостатком общего сна и усталостью. Метод и дополнительные материалы служб здравоохранения приведены в science.html#regime-method. Существующая арифметика сна и хранение данных сохранены. Добавлены проверки возрастных границ, неизвестных и старых данных, вечернего расчёта и адаптации к младенцам/школьникам.

Проверка 1.10.1: npm test успешно; браузерные сценарии на 320/390/430 px без переполнения. Пример 16:00–18:00 и укладывание в 20:00 показывает 2 часа до укладывания, осторожную подсветку и сохраняется после обновления; ссылка на методику открывает нужный раздел.


## Версия 1.10.2 — иллюстрированные подсказки

Добавлены восемь подготовленных карточек: продолжительность, бодрствование, укладывание, пробуждения, ритуал, спальня, нагрузки, самочувствие. `sleep-tips.js` использует исходную иллюстрацию `sleep-tips-art.png` (1536×1024, без повторного сжатия); CSS показывает соответствующую карточку целиком. Содержимое изображений не заменяет текстовые рекомендации, температура на рисунке пояснена как пример, не обязательная норма.

От 1200 px подсказки — боковой sticky-блок, ниже — отдельный блок после содержимого. Доступны стрелки, клавиши влево/вправо, скрытие и повторное открытие; свайп предусмотрен без автопрокрутки и без блокирования вертикального скролла. При переходе между экранами выбирается подходящая первая карточка; форма входа не содержит карусель. Компонент не читает и не отправляет ответы, не использует хранилище или внешние сервисы.

Проверка браузером: все 8 карточек стрелками, циклический переход, клавиатура, скрытие/показ, начальные карточки результата/дневника/главной, загрузка исходника, отсутствие переполнения 320/390/430 px и боковое расположение при 1348 px. Свайп реализован, но физическое касание на настоящем телефоне отдельно не тестировалось. Прежние расчётные тесты npm test проходят.
